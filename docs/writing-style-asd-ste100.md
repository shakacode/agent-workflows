# ASD-STE100-Inspired Writing Style

Lead with the outcome, decision, or request, then explain why. Preserve evidence.
Write for the reader. Use familiar words and exact domain terms; keep context close.
Prefer short sentences, active voice, and one main idea per sentence.
Be brief. Do not narrate obvious changes; keep detail proportional to the work.
Aim for grade 8 in broad prose and grade 12 in technical prose. Scores are rough guides.

## Scope

Apply the ASD-STE100-inspired constraints below only to human-facing
technical-documentation prose. Do not apply prose simplification to source
code, machine-readable content, or exact interface and protocol text.

## Technical-documentation constraints

- Use short, direct sentences and make instructions explicit.
- Prefer one action or one main idea in each sentence when this does not change
  the technical meaning.
- Use consistent project terminology. Do not invent replacement terms for
  precise technical nouns or verbs.
- Preserve exact identifiers, API names, commands, flags, paths, templates,
  evidence, quoted text, protocol markers, machine-readable protocol fields,
  and other required literals.
- Preserve technical meaning and safety conditions when simplifying prose.

## Authority and review

This adapter is independently authored guidance. It is not the ASD-STE100
specification or dictionary, and using it does not establish certification or
conformance. Formal ASD-STE100 work requires access to an authorized
specification and review by a qualified human.
